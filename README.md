# research-mcp

MCP-сервер для ML. Подключается к Claude Code, Codex CLI или любому другому MCP-клиенту и даёт агенту
доступ к свежим данным: статьи, GitHub, Hugging Face, форумы, веб.

Зачем: знания модели устаревают. Агент советует модели годичной давности, качает bf16 там, где хватило бы FP8, и
гадает при ошибках вместо того, чтобы найти issue с исправлением. С этим сервером он проверяет всё по живым
источникам.

Что умеет:

- показать, какие модели вышли под задачу за последние месяцы, и сравнить их (размер, контекст, лицензия,
  бенчмарки из карточек);
- подобрать веса под вашу видеокарту: bf16, FP8, INT8, GGUF;
- посчитать память и время для инференса, LoRA, QLoRA и полного fine-tune, а для моделей картинок и видео — под
  ваше разрешение, число кадров и шагов, с планом выгрузки в RAM, если модель не помещается;
- найти по тексту ошибки issues и PR с исправлением и проверить, не устарели ли версии библиотек;
- найти, что реально используют в сообществе: LoRA и чекпоинты на Civitai, ноды ComfyUI, обсуждения моделей на
  Hugging Face («медленно на 5090», «какой квант работает»);
- найти видео на YouTube и прочитать их по субтитрам с таймкодами: агент цитирует нужный момент ссылкой на секунду;
- помнить, что вы уже пробовали и с каким результатом, и не предлагать то, что не сработало;
- найти свежие методы под конкретную задачу («сэмплер лучше res_multistep при том же числе шагов») с цифрами из
  статей и ссылкой на код;
- показать, что внутри датасета, и найти код к статье;
- разобраться в предметной области как специалист, прежде чем советовать: найти и прочитать обзоры, эталонные
  датасеты, более новые работы, которые на них ссылаются, и работы по каждому понятию и решению (например, для разметки видео: атомарные действия,
  гранулярность, словарь меток, границы во времени, согласованность разметчиков), собрать знания с источниками
  и только потом предложить пайплайн;
- проверить ваш план, схему разметки или пайплайн по чек-листу специалиста и выученным ошибкам;
- перед исследованием задать уточняющие вопросы, если задача описана неполно;
- записать результаты со ссылками в один файл `RESEARCH.md`;
- в начале новой сессии рассказать, что вышло по вашим темам с прошлого раза: новые модели и их кванты,
  LoRA и workflow на Civitai, ноды ComfyUI, статьи, релизы того, на что ссылается тема. Проверка идёт в фоне
  не чаще раза в сутки, каждая новость показывается один раз.

Ключи не нужны, но с бесплатными ключами поиск лучше (см. «Ключи»).

## Установка

Отправьте агенту.

Claude Code:

```text
Установи MCP-сервер research: выполни
curl -fsSL https://raw.githubusercontent.com/PRISSET/research-mcp/main/scripts/install.sh | bash -s -- --agent claude --agent-rules
и скажи, чем закончилось.
```

Codex:

```text
Установи MCP-сервер research: выполни
curl -fsSL https://raw.githubusercontent.com/PRISSET/research-mcp/main/scripts/install.sh | bash -s -- --agent codex --agent-rules
и скажи, чем закончилось.
```

Скрипт клонирует репозиторий в `~/research-mcp`, ставит uv и зависимости и регистрирует сервер только в том
агенте, для которого вы его ставите. Флаг `--agent-rules` добавляет в его глобальные инструкции
(`~/.claude/CLAUDE.md` для Claude Code, `~/.codex/AGENTS.md` для Codex) короткое правило: проверять модели и
версии через этот сервер. После установки перезапустите агента. Нужны оба агента сразу — `--agent all`.

Сервер лёгкий: в простое около 80 МБ RAM, во время поиска по прочитанному около 250 МБ, torch и видеокарта не
нужны. При каждом запуске он сам обновляется с GitHub, если вы не меняли файлы в папке установки.

Флаги установщика: `--agent claude|codex|all`, `--notebook FILE`, `--lang ru|en`, `--no-embed` (только поиск по словам), `--dir PATH`,
`--no-register`, `--remove-agent-rules`.

## Примеры запросов

> Какие открытые модели сейчас лучше всего делают lip-sync на 8 ГБ?

> Какую версию весов Qwen3-8B качать под RTX 3060 Ti?

> Хватит ли 24 ГБ на QLoRA для Qwen3-14B с контекстом 8k и сколько займёт обучение на 200M токенов?

> vLLM падает с «Missing modality» на Qwen3-Omni, разберись.

> Помоги составить схему разметки 3-секундных клипов с атомарными движениями для LoRA.

В Claude Code есть команды `/mcp__research__research <тема>` и `/mcp__research__fix_error <ошибка>`.

## Инструменты

| Для чего | Инструменты |
|---|---|
| Уточнить задачу | `research_brief` |
| Стать специалистом | `study_topic` (изучить область по аспектам и сразу прочитать лучшее), `review_plan` (разобрать план или схему) |
| Модели | `latest_models`, `model_variants` (и сравнение моделей), `estimate_resources`, `dataset_info` |
| Поиск | `research_sweep` (статьи, модели, репозитории, issues, сообщество: Civitai, ноды ComfyUI, обсуждения HF, HN; YouTube; веб), `find_methods`, `find_papers` (и граф цитирований), `github_search`, `hf_search` |
| Чтение | `fetch` (страницы и полные тексты статей), `search_fulltext` (поиск по прочитанному), `evidence` (цифры и проверка утверждений), `source_info` (оценка, код, что пишут другие) |
| Ошибки и версии | `diagnose_error`, `check_versions` |
| RESEARCH.md | `notebook_read`, `notebook_write`, `notebook_add_source` |

Источники: OpenAlex, arXiv, Semantic Scholar (с ключом), GitHub, Hugging Face, Civitai, реестр нод ComfyUI, Hacker
News, Stack Overflow, Reddit (через свой Redlib), веб (SearXNG, Tavily или Brave; без них агент ищет своим веб-поиском). Каждому источнику ставится оценка от A (официальный) до D (заброшенный или
спорный).

Расчёты `estimate_resources` сделаны по формулам, а не по замерам. Погрешность обычно до 15%, допущения
выводятся вместе с ответом.

Для моделей изображений и видео (FLUX, Qwen-Image, Wan, MiniMax-H3 и т. п.) `estimate_resources` работает с
разрешением, числом кадров, шагов и CFG (`width`, `height`, `frames`, `steps`, `cfg`, `variant`). Компоненты
(денойзер, текстовый энкодер, VAE) и их точный размер берутся из заголовков safetensors в репозитории. Ответ
содержит пиковую VRAM по этапам ComfyUI, время на шаг и на весь ролик, а если модель не помещается, то план
выгрузки в RAM и сколько RAM для него нужно. Проверка: H3, 1344×768, 124 кадра, 10 шагов на A6000. Расчёт дал
6,2 минуты, реальный прогон занял 6,8.

## RESEARCH.md

Один файл на все исследования. Сверху оглавление, ниже по разделу на тему: вопрос, выводы, знания специалиста
(понятия, решения, практики, ошибки, метрики, инструменты — у каждого пункта источники), журнал экспериментов
(что меняли, настройки, результат, итог) и источники с заметками.
`study_topic` считает тему изученной (`expert_ready`), когда знаний и прочитанных источников достаточно для
выбранной глубины. Файл можно править руками: сервер меняет только текст между метками `<!-- research:… -->`. Добавить в
него можно только источники, которые нашли инструменты, так что выдуманных ссылок не будет.

## Ручная установка

```bash
git clone https://github.com/PRISSET/research-mcp.git && cd research-mcp
uv sync --extra fulltext --extra embed
```

Затем зарегистрируйте сервер в своём агенте. Claude Code:

```bash
claude mcp add research -s user -- uv --directory "$(pwd)" run research-mcp
```

Codex:

```bash
codex mcp add research -- uv --directory "$(pwd)" run research-mcp
```

Для Codex поднимите таймауты в `~/.codex/config.toml`:

```toml
[mcp_servers.research]
startup_timeout_sec = 120
tool_timeout_sec = 300
```

Другие клиенты (stdio):

```json
{ "mcpServers": { "research": { "command": "uv", "args": ["--directory", "/путь/к/research-mcp", "run", "research-mcp"] } } }
```

## Веб-поиск

Без настройки агент ищет в вебе своим поиском (WebSearch в Claude Code), а MCP подсказывает ему запросы и читает
найденные страницы. Свой встроенный поиск без ключей у MCP плохой: DuckDuckGo блокирует его как бота, а Bing
отдаёт нерелевантные страницы. Чтобы встроенный поиск работал бесплатно и без лимитов, поставьте локальный
[SearXNG](https://github.com/searxng/searxng). Это метапоиск, который опрашивает Google, Bing, Brave и другие
поисковики и объединяет результаты. Docker не нужен:

```bash
cd ~/research-mcp && uv run kb searxng install     # или установщик с флагом --searxng
```

Команда ставит SearXNG в `~/.local/share/research-mcp/searxng` (отдельный venv, только `127.0.0.1:8888`), на
Linux включает пользовательский сервис `research-searxng` и сама прописывает `SEARXNG_URL`. Удалить:
`uv run kb searxng uninstall`. Свой SearXNG на другом адресе задаётся через `kb keys set SEARXNG_URL http://…`
(в его `settings.yml` должен быть включён формат `json`). Порядок движков: SearXNG, Tavily, Brave.

## Reddit

Reddit закрыл API для новых приложений и отвечает 403 любым скриптам. Читать его можно через свой
[Redlib](https://github.com/redlib-org/redlib), частный фронтенд Reddit. Он собирается из исходников через
`cargo`, Docker не нужен:

```bash
cd ~/research-mcp && uv run kb redlib install      # или установщик с флагом --redlib
```

После установки `fetch` читает треды целиком: пост и дерево комментариев (сначала лучшие, с оценками и пометкой
автора поста), а `research_sweep` ищет по Reddit. Команда собирает Redlib в `~/.local/share/research-mcp/redlib`
(только `127.0.0.1:8889`), на Linux включает сервис `research-redlib` и прописывает `REDLIB_URL`. Сборка
занимает несколько минут, нужен Rust (`cargo`). Сейчас ставится форк Silvenga: основная ветка Redlib с сентября
2025 года не запускается с ошибкой «Failed to create OAuth client»
([#485](https://github.com/redlib-org/redlib/issues/485)), а форк работает. Переключить источник можно через
`KB_REDLIB_REPO` и `KB_REDLIB_BRANCH`. Удалить: `uv run kb redlib uninstall`.

## Ключи

Работает и без ключей. Ключи необязательные и бесплатные (кроме Brave): каждый включает или улучшает одну
площадку. Хранятся в одном файле `~/.config/research-mcp/keys.env` (права 600), его читает каждый процесс сервера.

Команды запускаются из папки, куда установлен сервер (по умолчанию `~/research-mcp`):

```bash
cd ~/research-mcp
uv run kb keys                                  # какие ключи заданы, что даёт каждый и где его получить
uv run kb keys set TAVILY_API_KEY tvly-xxxx     # добавить или заменить ключ
uv run kb keys set TAVILY_API_KEY ""            # удалить ключ
```

После добавления перезапустите сессию агента (Claude Code / Codex), чтобы сервер перечитал ключи.

| Ключ | Площадка | Что даёт | Где получить |
|---|---|---|---|
| `SEARXNG_URL` | веб-поиск | адрес своего SearXNG: бесплатно и без лимитов; заполняется сам при `kb searxng install` | см. «Веб-поиск» |
| `REDLIB_URL` | Reddit | адрес своего Redlib: треды с комментариями и поиск по Reddit; заполняется сам при `kb redlib install` | см. «Reddit» |
| `TAVILY_API_KEY` | веб-поиск | встроенный поиск для агентов; без ключа агент ищет своим веб-поиском. Бесплатный план без карты | [app.tavily.com](https://app.tavily.com) |
| `BRAVE_API_KEY` | веб-поиск | поиск Brave вместо Tavily или вместе с ним; нужна карта, есть ежемесячный бесплатный кредит | [api-dashboard.search.brave.com](https://api-dashboard.search.brave.com) |
| `GITHUB_TOKEN` | GitHub | репозитории и issues: 5000 запросов в час вместо 60. Хватает токена без прав (classic, без галочек) | [github.com/settings/tokens](https://github.com/settings/tokens) |
| `HF_TOKEN` | Hugging Face | закрытые (gated) модели — Llama, Gemma, часть FLUX: без токена их карточки, конфиги и размеры весов отвечают 401, и `fetch`, `model_variants`, `estimate_resources` их не видят; выше лимит API (без токена 500 запросов за 5 минут). Токен с правом Read; доступ к самой gated-модели нужно один раз принять на её странице | [huggingface.co/settings/tokens](https://huggingface.co/settings/tokens) |
| `S2_API_KEY` | Semantic Scholar | включает его в поиск статей, граф цитирований и «что пишут другие»; без ключа он выключен | [semanticscholar.org/product/api](https://www.semanticscholar.org/product/api#api-key-form) |
| `OPENALEX_API_KEY` | OpenAlex | поиск статей: суточный лимит в 10 раз больше | [openalex.org/settings/api](https://openalex.org/settings/api) |
| `CIVITAI_API_KEY` | Civitai | модели и LoRA, доступные только после входа, выше лимиты | [civitai.com/user/account](https://civitai.com/user/account) → API Keys |

Hugging Face (кроме gated-моделей), arXiv, YouTube, реестр нод ComfyUI и Hacker News работают без ключей. Reddit
работает через свой Redlib (см. «Reddit»), а без него агент ищет Reddit своим веб-поиском (`site:reddit.com`).

Вместо файла ключ можно передать переменной окружения при регистрации сервера, она важнее файла:

```bash
claude mcp add research -e GITHUB_TOKEN=ghp_xxxx -- uv --directory ~/research-mcp run research-mcp
```

## Настройки

Переменные окружения, все необязательные:

| Переменная | Что делает |
|---|---|
| `RESEARCH_NOTEBOOK` | путь к блокноту, по умолчанию `~/research/RESEARCH.md` |
| `RESEARCH_LANG` | `ru` или `en` |
| `RESEARCH_NSFW` | `1` включает в поиск по Civitai модели для взрослых |
| `RESEARCH_KEYS` | другой путь к файлу ключей |
| `KB_MODEL_IDLE` | через сколько секунд простоя выгружать модель эмбеддингов (по умолчанию 600) |
| `KB_KEEP_DAYS` | сколько дней хранить прочитанное, которое не попало в блокнот и не находилось поиском (по умолчанию 60, `0` — хранить всё) |
| `KB_AUTO_UPDATE` | `0` отключает автообновление |
| `KB_HTTP_CACHE` | `0` отключает кеш ответов API |
| `KB_DATA_DIR` | где хранить локальную базу (по умолчанию `data/`) |

В `data/` лежит кеш: прочитанные тексты, векторы и ответы API. Источники из блокнота хранятся всегда, остальное
удаляется после `KB_KEEP_DAYS` дней без использования (`uv run kb base prune` делает это вручную). Кеш можно
удалить целиком, блокнот от него не зависит.

Поиск по прочитанному: BM25 плюс векторы статической модели
[potion-retrieval-32M](https://huggingface.co/minishlab/potion-retrieval-32M) (model2vec, без torch, ~130 МБ RAM,
грузится при первом поиске). Запросы к нему пишите по-английски. Качество проверяется `eval/run_search_eval.py`.

## Разработка

```bash
uv sync --extra fulltext --extra embed --group dev
uv run --group dev pytest -q
uv run kb update --check     # есть ли новая версия
```

Код в `src/kb/`: `research/` (поиск по платформам, модели, ML-расчёты), `process/` (тексты, векторы, гибридный
поиск), `critic/` (оценки источников), `notebook.py`, `update.py`, `mcp/server.py`.
